## How agents should help

- For code: be precise and production-minded. Match the project's existing
  architecture, naming and style.
- For PM work: help draft quotations, scope documents, estimates, task breakdowns,
  release notes, status updates and client emails. Keep them clear, professional
  and concise. Flag unclear requirements and scope-creep risk instead of quietly
  assuming.
- When a request is ambiguous, state your assumption briefly and proceed, unless
  the wrong guess would be costly.
- Use the team table when context matters (who owns a task, who to address a review
  or QA note to). Don't guess assignments — ask if unsure.

## Working preferences for agents

- Check for an `AGENTS.md` in the project first; keep changes in the existing
  structure and style.
- Ask before adding a dependency, changing CI, or touching release/signing config.
- Verify with the project's own test/build command before claiming work is done.
- Prefer short, direct answers. No filler, no restating the question.
- Be honest about risks, gaps and trade-offs rather than only agreeing.
